# skill-methodology-absorb

> 把开源技能（GitHub 上的 Claude / WorkBuddy Skill）的方法论安全吸收进自研技能的 WorkBuddy / Claude Code 技能。

## 简介

把别人的技能"吸收"进自己的技能时，最大的风险不是技术，是设计——模块挂错位置会让主文件变胖，硬合并会让触发词污染。本技能沉淀了一整套"方法论吸收"的工程纪律：从镜像下载、全量通读、三清单分析、硬合并可行性判断，到懒加载挂载位置铁律、主文件体积预算、交付前验证清单，全部以可执行的规则与命令呈现。

当用户提出以下诉求时自动触发：

- "把某个技能合并进我的技能"
- "吸收这个技能的能力"
- "这两个技能能不能合并"
- "帮我改造我的技能"

覆盖范围：镜像下载、硬合并可行性判断框架、懒加载挂载位置铁律、主文件体积预算、交付前验证清单。

## 功能特性

- **五条铁律**：违反任何一条都要重做
  - 模块只能挂"可选支线"，不能挂"必经路径"（否则是伪懒加载）
  - 硬合并前先查三个冲突（触发词污染 / 交付物冲突 / 上下文预算）
  - 主文件体积预算制（改前记字节数、定上限、改后实测）
  - 备份策略（默认跳过，仅用户主动要求时才做，且备份必须放技能目录之外）
  - 写完必须统一换行符（Windows Python 写入会把 LF 变 CRLF，虚增体积）
- **五步标准流程**：拿到源技能 → 全量通读做三张清单 → 出三个方案让用户选 → 按铁律执行 → 交付前逐项实测
- **硬合并可行性判断框架**：三冲突任一成立即放弃"合成一个"，改用"能力吸收 + 独立并存"
- **懒加载挂载位置铁律**：「每题必过」的内容压缩内嵌主文件；「满足条件才用」的内容独立成可选支线模块；「历史文档」一律外置
- **交付前验证清单**：文件清单与换行符、主文件体积、frontmatter 字段、新增内容就位、代码块配对、原有内容未丢，逐项实测不靠感觉
- **许可与署名指引**：吸收开源内容前先看协议，在目标技能中标注原作者（如 `方法论源自 @XXX（MIT 协议）`）

## 工作原理

### 三冲突判断表（铁律二）

| 冲突类型 | 检查方法 | 后果 |
|---------|---------|------|
| 触发词污染 | 把两个技能的 description 触发词摆在一起看，有没有场景重叠/包含关系 | 用户说 A 场景被路由到 B 流程 |
| 交付物冲突 | 两个技能最终产出什么？形态是否互斥（如 文档 vs 代码） | 硬合并后指令互相打架 |
| 上下文预算 | 两边总体积相加，对比目标技能当前体积 | 主文件爆炸，触发质量下降 |

### 三方案决策（第三步）

- **方案 A：能力吸收 + 独立并存**（通常最优）
- **方案 B：深度合并成一个**（通常不推荐）
- **方案 C：技能族 + 总控路由**（中期演进）

### 三张清单分析（第二步）

1. **重叠区**：两边都在做的事（可择优统一）
2. **互补区**：一方有另一方没有的（合并的价值所在）
3. **冲突区**：不能硬合的理由（见铁律二）

## 安装与使用

把本仓库的目录内容复制到你的技能目录下，文件夹名保持 `skill-methodology-absorb`：

- WorkBuddy / CodeBuddy：`~/.workbuddy/skills/skill-methodology-absorb/`
- Claude Code：`~/.claude/skills/skill-methodology-absorb/`

重启会话后即可通过触发词自动匹配。

技能执行中涉及的两个实用命令：


## 注意事项

- **不换行符校验必踩坑**：Windows 上 Python 文本模式写入会把 `\n` 转成 `\r\n`，每行 +1 字节，可能误判"超预算"。处理完后必须跑一遍换行符检测脚本（SKILL.md 内置）。
- **备份不进技能目录**：`~/.workbuddy/skills/` 下的子目录只要含 SKILL.md 就会被扫描成重复技能，备份必须放技能目录之外，备份后验 MD5 一致再动手。
- **默认不备份**：用户 2026-09-30 已明确废止备份步骤；仅当用户主动说「先备份一下」时才执行。
- **历史日志外置**是给主文件腾空间最快的手段。
- **交付前逐项实测**，不靠"应该没问题"。发现超预算或有瑕疵时，如实告知并修掉，不要隐瞒。
